# Engineering Guidelines

- Prefer the simplest correct solution. Keep complexity proportional to actual needs.
- Follow existing patterns. Avoid unnecessary abstractions, layers, dependencies, and defensive code.
- Make minimal, focused changes. Avoid speculative features and unrelated refactoring.
- Do not add tests by default. Add them when requested or justified by meaningful risk.
- Keep verification proportional to risk. Stop when the task is correctly completed and sufficiently verified.
