# Engineering Guidelines

- Solve the requested problem with the simplest complete, correct solution. Avoid unnecessary features and complexity.
- Follow existing patterns. Prefer clear, straightforward code; introduce abstractions or dependencies only when genuinely needed.
- Keep changes focused. Preserve unrelated behavior and existing user changes; avoid opportunistic refactoring.
- Test and verify proportionally to risk. Prefer focused checks over excessive tests, mocks, or scaffolding. Report what was verified and any remaining uncertainty.
