# Presentation module

`frame/` owns role palettes, theme presets and ANSI-safe border/gradient geometry through `Border`, `Box`, `Gradient` and `Palette`. Both this package and UI components use it directly; it has no dependency on its parent. Frame algorithm tests live there, while transcript/sidebar integration and hit-geometry tests remain here. `tooldetail/` owns complete tool-detail documents. Keep component layout with its geometry rather than introducing forwarding layers just to split files.

`Transcript` renders immutable `[]session.Item`. User messages are narrow right-aligned bubbles titled `你`; consecutive assistant/thinking/tool records share a left bubble titled `Options.AssistantTitle` (fallback `助手`). System/compaction/branch summaries use a `系统` frame containing one clipped synopsis. Full saved text remains in the projection. Adjacent message frames have no extra blank rows; Markdown paragraphs retain their own spacing.

User text and image blocks project into one bubble. Numbered `[imageN]` references are colored blue without underline only when backed by saved `Item.Images`; `Document.ImageLinks` supplies zero-based item/index and terminal row/cell hit ranges. The UI resolves clicks against that session's saved bytes. Cache keys use image count, never base64 data; cached links receive the same section offsets as blocks. Incomplete references wrapped across very narrow rows are deliberately not clickable.

Role frame edge colors are compiled from the reference UI palettes: mint user, blue assistant, purple system/editor, neutral tools. Everything is transparent except the selected sidebar card (`82;85;88`). Markdown uses Glamour and tool source uses Chroma. Untrusted controls are removed before rendering. ANSI-aware wrapping handles Unicode and narrow widths.

Every tool run, including a single call (`1 calls`), defaults to a collapsed `tool-group:<first ID>`; one blank row separates the entire group from both preceding and following prose, not the header from its children. Leading/trailing groups do not add empty rows at the bubble boundary. Opening a group reveals children indented two cells, reducing their available width accordingly. `Options.ExpandTools` expands groups/cards; explicit `Options.Expanded[id]` overrides it in both directions. Worker tasks themselves are always expanded and ignore per-task fold entries. Click handlers toggle `!Block.Expanded`, not a possibly absent map entry. With `ShowToolActivity` enabled for a busy session, the latest group without following assistant prose animates the full calls header, including tool counts, failures and token estimates, with a foreground highlight sweep over its unchanged base colors, without a separate Running heading; the latest three calls appear below it as indented summaries or full Worker cards. Completed Workers stay expanded only while within those three; older Workers are omitted like other tools.  This is not full tool-result expansion. The activity list immediately follows the group header without a blank row. Recent-call entries use the normal tool layouts, hit targets and per-tool fold state, so ordinary tools can be expanded or collapsed without opening the group. While active, collapsed groups show the recent-call preview; expanded groups show all calls without duplicating the preview. Both states animate the active group label. Prose, session boundaries or idle state remove it. Cache invalidation includes the active group identity, including when a later section closes its lifetime.

Read keeps a compact path/parameter line and up to eight terminal rows of saved source with original line numbers, plus a truncation marker when needed. Edit/write cards contain only recorded diff, or explicitly labeled replacement/write previews when no diff was saved; failures retain their error messages. They omit parameter/result sections and shrink to visible content. Codemode shows highlighted JavaScript and actual internal calls. Worker prefers native `details` snapshots and displays non-foldable task rows with status, preset, objective, real usage/timing and result summaries. Model/provider and session mode are hidden. Between the objective and conclusion, a non-interactive steps section combines tools and thinking in snapshot order and shows only the latest three steps. Thinking uses `!`, strips bold markers and splits consecutive headings; it is not duplicated below the list. The header is `≡ Activity` without a total count, with `… n items (已折叠)` for omitted entries. Totals include reported tool calls plus retained thinking entries, without guessing discarded thinking history. Worker step headers omit outcome counts and token usage. Ordinary calls groups show only nonzero failure counts, never success counts. The conclusion remains unchanged, with ordered explanatory text while no conclusion is available; slot chatter is excluded. Live and completed Workers remain in calls groups. Worker groups and batch cards follow ordinary explicit/global expansion settings, never runtime-driven automatic expansion. A collapsed outer group renders only its header, regardless of child or global expansion state. Missing metadata is not fabricated; historic JSON and plain-text results have structured fallbacks. No preview reads current disk files or executes anything.

Bash cards show the command without line numbers, optional parameters without section headings, and the first eight terminal rows of literal output (or `(no output)`); longer output ends with a truncation marker. The frame shrinks to visible content, while complete output remains in session data. Ask-question cards render question text and a single option list, highlighting selected answers and showing custom responses, multi-question/multi-select, waiting and cancelled states without repeated result/metadata sections. Search/list tools and unknown/MCP tools use one dim parameter-summary line and up to eight terminal rows of structured or literal results. They omit Parameters/Result/Metadata headings and extra metadata, mark truncated results, and shrink the frame to visible content. JSON objects use labeled fields; uniform arrays of two or more records use aligned tables when all scalar values fit, with deterministic column ordering. Narrow, sparse, nested, multiline and source/attachment-bearing records fall back to the full field view without clipping values. Invalid JSON stays literal text. Collapsed previews surface useful field values/collection counts rather than only a field count, show line counts for multiline text, and distinguish empty results from waiting output. Failed edits/writes preview the actual error rather than the requested change. Image bytes are never included in these tables or summaries. Bash, read and generic previews remain bounded even when expanded; full saved data is retained in the session. Other existing expansion controls reveal their saved output; no new disk reads or pagination state are introduced.

`Document.Blocks` uses zero-based start-inclusive/end-exclusive terminal line offsets, including frames and intentional group spacing. A group covers only its summary row. Ordinary tool blocks cover their invocation/result; Worker batch headers alone are foldable; task content has non-foldable ranges and clicking it never toggles the parent. Hidden children have no blocks. UI adds viewport origin and subtracts scroll offset.

`State.MessageCount` and `Item.MessageIndex` describe native messages on the full current branch, independent of terminal lines/content blocks/folding. They propagate to `Document.MessageCount`/`Block.MessageIndex`. A collapsed group carries its last member's ordinal; an expanded group header uses zero so unseen children do not advance the position. Worker tasks share their parent message ordinal.

`Sidebar` is exactly width × height, including a full outer frame and inset separators. SESSION contains name/cwd/optional Git and CTX progress/use. STATS has lowercase `in/out` and `cache/cost` in two aligned columns. Eligible Codex quota adds optional rows. RECENTS heads the region; + New session is a fixed full-inner-width click target below the history viewport, separated by one blank row. The viewport shows up to five single-row history names, bounded by height to retain room for an open-session card. Clicking a row restores its session. HistoryOffset is clamped by SidebarGeometry; names are indented without ordinals and truncated. Hover changes the name to pale-purple foreground without a background; the current session alone is not highlighted. All-motion mouse reporting preserves transcript dragging; hover is derived from pointer coordinates and current layout, including after scroll and refresh. A subtle scrollbar spans the list when history overflows. The UI supplies all saved sessions and independently routes history/open-tab wheel scrolling. A single blank row, without a separator, precedes the two-row open-session cards; there is no collapse or SESSIONS heading. `SidebarGeometry(height, context)` is authoritative for optional rows, capacity and clicks. Model/thinking controls belong to the input footer, not the sidebar.

No subprocesses, network, settings mutation, credential access or model execution occur in this package.
