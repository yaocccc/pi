# Presentation module

`Transcript` renders immutable `[]session.Item`. User messages are narrow right-aligned bubbles titled `你`; consecutive assistant/thinking/tool records share a left bubble titled `Options.AssistantTitle` (fallback `助手`). System/compaction/branch summaries use a `系统` frame containing one clipped synopsis. Full saved text remains in the projection. Adjacent message frames have no extra blank rows; Markdown paragraphs retain their own spacing.

User text and image blocks project into one bubble. Numbered `[imageN]` references are colored blue without underline only when backed by saved `Item.Images`; `Document.ImageLinks` supplies zero-based item/index and terminal row/cell hit ranges. The UI resolves clicks against that session's saved bytes. Cache keys use image count, never base64 data; cached links receive the same section offsets as blocks. Incomplete references wrapped across very narrow rows are deliberately not clickable.

Role frame edge colors are compiled from the reference UI palettes: mint user, blue assistant, purple system/editor, neutral tools. Everything is transparent except the selected sidebar card (`82;85;88`). Markdown uses Glamour and tool source uses Chroma. Untrusted controls are removed before rendering. ANSI-aware wrapping handles Unicode and narrow widths.

Every tool run, including a single call (`1 calls`), defaults to a collapsed `tool-group:<first ID>`; one blank row separates the entire group from following prose, not the header from its children. Prose followed by a tool group has no added blank row, and a trailing group adds no blank row. Opening a group reveals children indented two cells, reducing their available width accordingly. `Options.ExpandTools` expands groups/cards/tasks; explicit `Options.Expanded[id]` overrides it in both directions. Click handlers toggle `!Block.Expanded`, not a possibly absent map entry.

Read/write retain saved source/line numbers; edit prefers recorded diff. Codemode shows highlighted JavaScript and actual internal calls. Worker prefers native `details` snapshots and displays independently foldable task rows with status, routing, objective, real usage/timing and result summaries. Live Worker invocations break tool runs and default to expanded cards/tasks, showing the latest ten visible activities (thinking/slot chatter is excluded before limiting). On completion they rejoin adjacent tool groups. Automatic expansion never writes manual fold state, and explicit overrides still win; historical snapshots saying running do not enable it without the live invocation flag. Missing metadata is not fabricated; historic JSON and plain-text results have structured fallbacks. No preview reads current disk files or executes anything.

All ordinary tools, including unknown/MCP names, share saved-result visualization. JSON objects use labeled fields; uniform arrays of two or more records use aligned tables when all scalar values fit, with deterministic column ordering. Narrow, sparse, nested, multiline and source/attachment-bearing records fall back to the full field view without clipping values. Invalid JSON stays literal text. Collapsed previews surface useful field values/collection counts rather than only a field count, show line counts for multiline text, and distinguish empty results from waiting output. Failed edits/writes preview the actual error rather than the requested change. Image bytes are never included in these tables or summaries. Existing expansion controls reveal the complete saved output; no new disk reads or pagination state are introduced.

`Document.Blocks` uses zero-based start-inclusive/end-exclusive terminal line offsets, including frames and intentional group spacing. A group covers only its summary row. Ordinary tool blocks cover their invocation/result; expanded worker parents and nested task headers have separate non-overlapping click ranges. Hidden children have no blocks. UI adds viewport origin and subtracts scroll offset.

`State.MessageCount` and `Item.MessageIndex` describe native messages on the full current branch, independent of terminal lines/content blocks/folding. They propagate to `Document.MessageCount`/`Block.MessageIndex`. A collapsed group carries its last member's ordinal; an expanded group header uses zero so unseen children do not advance the position. Worker tasks share their parent message ordinal.

`Sidebar` is exactly width × height, including a full outer frame and inset separators. SESSION contains name/cwd/optional Git and CTX progress/use. STATS has lowercase `in/out` and `cache/cost` in two aligned columns. Eligible Codex quota adds optional rows. There is no SESSIONS heading; + New session has one blank row below it, then two-row cards. `SidebarGeometry(height, context)` is authoritative for optional rows, capacity and clicks. Model/thinking controls belong to the input footer, not the sidebar.

No subprocesses, network, settings mutation, credential access or model execution occur in this package.
