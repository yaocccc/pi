# Pi Workbench：多会话原型

独立终端入口，不是历史 session 选择器；启动的 Pi 会额外加载一个轻量元数据桥接扩展。左侧只列本次启动的 Pi 实例；右侧显示选中实例的原生终端画面。每个实例拥有独立进程、PTY、会话和终端缓冲区，切换只改变显示与输入目标，后台仍运行。

## 启动

需要 **Linux、Node.js 22.19+、PATH 中可执行的 `pi`**，以及交互终端。依赖仅安装在本目录，不修改 Pi 或 `extensions` 的依赖。

```bash
cd ~/.pi/agent/workbench
npm ci
npm start -- --cwd /你的项目路径
```

也可从任意目录启动：

```bash
node ~/.pi/agent/workbench/src/main.js --cwd "$PWD"
```

`--pi /path/to/pi` 可指定 Pi 可执行文件（不是 shell 命令字符串）。`--` 后传给每个新实例的 Pi 选项，例如 `-- --model provider/model`、`-- --no-session`。不支持 `--continue`、`--resume`、`--session`、`--session-id`、`--fork`，避免多个进程写同一会话；也不支持切换非交互输出模式。每次新建都启动新的会话，不恢复历史记录。不要把此入口作为当前 Pi 的 bash 工具运行；应在普通终端的新窗口/标签页启动。

依赖：`node-pty` 1.1.0、`@xterm/headless` 6.0.0、Unicode 11 addon、`string-width`。当前机器安装和真实 PTY 加载已通过；其他 Linux 环境若无法使用预编译模块，需要 node-pty 文档要求的 Python、make 和 C++ 编译工具。

## 操作

默认启动一个实例并显示左侧栏（无需 `--two`）。点击左下角 **`new`** 启动新的独立实例，点击会话行切换。不设人为会话数量上限，新建按钮始终可用；实际数量受内存、CPU、进程数及模型并发额度限制，每次按需启动。`--two` 仍仅预创建两个实例。

侧栏最底行左侧显示 **`new`**，右侧显示 **`«`**，点击底行最右四列可收起，当前 Pi 使用整个窗口宽度；左上角显示无背景的 **`»`**，点击左上第一行的四列范围可重新展开。符号仅覆盖左上一格；按钮点击不会发送给 Pi，其他区域仍使用 Pi 原生鼠标。会话列表会为底部按钮让出一行，滚动与选中项自动定位仍可用。

工作台没有键盘快捷键，也不拦截 Ctrl+G、Ctrl+C 等普通按键：所有键盘输入和粘贴均发送给当前 Pi，保留 Pi 原生快捷键、输入框与页脚。

- 点击左下角 **`new`** 新建；点击列表中的会话行切换。
- 在右侧使用 Pi 原生退出方式关闭会话；工作台不提供关闭按钮或确认弹层。
- 在右侧文字上左键拖选，使用 Pi 原生复制能力（取决于 Pi 配置及 wl-copy / xclip 等系统支持）；也可尝试 Shift+拖动后使用终端原生复制。工作台不提供复制按钮，不保存选区快照，不透传子进程 OSC 52，因此依赖该协议的子 Pi 复制方式不可用。
- 右侧点击、滚轮和拖动按子 Pi 请求的模式转发，扣除左栏宽度；拖动越过分隔线也保持坐标正确。左栏滚轮只滚动会话列表，不发送给 Pi。
- 关闭最后一个会话后工作台自动退出。没有“全部退出”快捷键；也可关闭终端窗口，由 SIGHUP 清理所有实例。

左栏宽 16 列，卡片左右各留一列 padding，分隔线另占一列。顶部显示粗体 `Sessions`，底部左侧为 `new`、右侧为 `«`；每个会话占两行，第一行显示序号和状态，第二行显示名称。当前卡片两行使用灰色背景（#525558），其他卡片保持透明；名称为浅灰色，idle 绿色、working 紫色、等待回答 黄色、done 青绿色、error 红色、starting/closing 灰色。过长名称及极长序号按终端列宽用 `…` 省略（支持中文及 emoji），优先保留完整状态。仅显示完整卡片，末尾不足两行时留空；名称与状态行均可点击切换。超出视口时用滚轮浏览，点击可见行切换；新建、切换和窗口缩放会保证选中项可见，后台输出不会打断手动滚动。

**底部无宿主状态栏或帮助栏**，右侧占满终端高度，Pi 原生页脚保留。通知及错误临时显示在左栏标题下方，仍可点击新建，不占右侧空间。少于 70 列或 10 行时侧栏自动隐藏，且不显示无法展开的药丸；手动收起状态会跨窗口缩放保留，扩大窗口后恢复药丸。自动隐藏但未手动收起时，扩大窗口会直接恢复侧栏。右侧键盘和鼠标仍可用；需要新建或切换时须扩大窗口，隐藏期间的提示会在侧栏恢复时显示。极小窗口显示调整尺寸提示。

## 状态与隔离

- 工作台自动注入 `src/bridge.js`，通过独立、带版本的元数据消息报告 `pi.getSessionName()` 和待回答问题数。名称在 `session_start` / `session_info_changed` 时刷新，因此 `/name` 或 autoname 异步命名在空闲、等待期间也会更新；不再把 OSC 7501 的状态消息当名称。尚未命名时名称行留空。自动命名可能因内容不足而保持未命名，工作台不会编造标题。
- `starting`：子进程启动中，尚未收到状态。
- `working` / `blocked` / `idle` / `done` / `error`：解析 Pi 原生 **OSC 7501** 根状态。本仓库真实 `ask_question` 的自定义 UI 不会自动上报原生 `blocked`，因此它额外发出 `ask-question:pending` 事件（只含当前与排队问题总数）；桥接将其发送给工作台，有待回答问题时优先显示“等待回答”，回答、取消或中断后恢复最近的原生状态。原生 `blocked` 仍涵盖其他问题、权限、认证等等待。无需读取屏幕文本，不传输问题摘要或答案，也不自动回答后台问题。
- 子进程退出（正常、错误或信号退出）后立即从侧栏移除，不保留 `exited` 卡片。当前实例退出时选中相邻实例，后台实例退出不改变当前选择。所有实例均关闭后工作台自动退出，等待资源清理并恢复终端；不会自动新建会话。启动失败的进程也会移除。
- 清除继承的 Herdr pane/session 标识，避免多个实例错误上报同一个外围 pane；不会移除 Worker 的限制环境变量。
- 工作台只托管当前实例，不枚举历史 session、不把 Worker 任务当会话、不调用 `switchSession`。

**进程隔离不等于文件隔离。** 多个实例共享指定 cwd，以及通常的 Pi 配置、模型凭证和会话存储目录。可能同时修改同一文件、竞争扩展配置或产生并发模型费用；没有跨实例文件锁/独立 worktree。不要在不同会话安排冲突写任务。各实例照常加载用户配置的扩展，具有各自后台连接的扩展也需自行支持多进程。

## 实现与限制

- `src/session.js`：node-pty 启动独立 Pi，持续消费所有实例输出，xterm 写入队列有高/低水位流控；终端查询回复只回到发起查询的实例。
- `src/screen.js`：xterm 解析 VT、备用屏幕、光标、颜色、Unicode 与 OSC 状态。宿主只输出解析后的单元格，**不原样转发**子进程控制序列。
- `src/view.js` / `src/main.js`：左右布局、选中实例输入、屏幕增量行绘制与光标坐标平移。不修改全局 Pi 安装；本仓库 `ask-question` 仅增加进程内等待计数事件，普通 Pi 不加载桥接、不输出额外控制序列。
- `src/bridge.js`：仅在工作台设置 `PI_WORKBENCH_BRIDGE=1` 并显式加载时启用，以 `OSC 777;pi-workbench;<base64 JSON>` 发送 `{version:1,name,pending}` 完整快照。宿主校验版本、长度和字段；每个 PTY 独立处理，原生状态不能覆盖未结束问题。需重启工作台和子 Pi 才能加载新桥接；第三方提问工具需主动集成该事件或原生 blocked 标志。
- `src/process-tree.js`：会话退出或宿主退出时清理资源，向拥有的 PTY 进程组和可枚举后代发送 TERM，600ms 后升级 KILL；PID 身份校验避免误伤重用 PID。退出关闭宿主鼠标上报，并恢复原屏幕、光标、换行和 raw/paste 状态。外部 SIGTERM/SIGHUP/SIGINT 同样触发清理。
- 关闭是**终止运行**，不是 detach；未完成模型回复、未保存输入/临时 UI 状态可能丢失。只有 Pi 已持久化的内容可之后恢复。没有后台守护、断线重连或跨工作台持久化列表。
- `src/mouse.js`：依据子终端鼠标模式转发点击/拖动/滚轮，捕获拖动直至释放。所有子进程 OSC 52（前台及后台）均被吞掉，禁止其任意改写宿主剪贴板。此边界不限制子进程直接访问本地剪贴板程序；独立进程不是安全沙箱。
- 不是完整终端模拟产品：不支持 Kitty 增强键盘、内联图片、子进程 OSC 52 透传、OSC 8 超链接或终端窗口标题转发。图片能力显式禁用；保留普通文字/颜色/原生键盘问答。复杂 emoji 的宽度可能与宿主字体/终端不同。
- 没有 cgroup/sandbox 级进程约束。关闭时已枚举的 detached 后代也会被终止，但提前 daemonize、重归父进程、逃离进程组的进程不保证可追踪。宿主 SIGKILL/掉电无法执行终端恢复和清理；如终端异常可在 shell 执行 `stty sane` / `reset`。
- 尚未人工截图验收；当前验证的是 headless 网格与真实 PTY 行为，不宣称完整兼容所有终端和插件。
